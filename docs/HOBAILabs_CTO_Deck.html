01
The product in one line

Plain-text story + a folder of media → a finished reel

Three front doors, one engine. Every door builds the same frames[] data model and calls the same agents/* stages. New modes are flags into the shared pipeline — never a fork.

Story /

HOB team turning a personal story script into a reel.

Brand /brand

Studio /studio

Prompt → reel

02
The defining principle

Realism preservation + test-cheap / finish-expensive

  • Real media is never AI-regenerated. Real photos/videos of a real person or product pass through the pipeline untouched. This is HOB's one irreplaceable asset — authenticity.
  • Per-shot model routing. Cheap models in Dev for iteration; premium models only for final / client renders. Cost discipline is automatic, not manual.
  • AI fills the gaps, not the subject. Synthetic stills (portraits, symbolic shots) are generated only where no real asset exists — and are gated for sanity and provenance.

Why it matters

An AI portrait of a named real person attacks the brand's credibility. The product rule is to prefer real-photo animation + symbolic AI, and treat AI-on-a-real-person as a consented, labelled exception under governance.

03
System context

A thin orchestrator over pluggable, degradable vendors

The engine owns the direction; every heavy capability is a vendor behind a seam that can fail without crashing the render.

  • LLM brain — OpenAI · Anthropic (direct) · Bedrock · Gemini, behind one chat() entry point with 3 tiers.
  • Image — fal.ai (Flux, Seedream, Nano Banana), OpenAI gpt-image.
  • Video — Kling, Higgsfield, fal (Seedance / Veo / Hailuo).
  • Lip-sync — Hedra (photo), SyncLabs (video).
  • Voice / Music / Safety — ElevenLabs · Suno · OpenAI Moderation.

Three independent vendor axes

Reasoning/vision/fast LLM (llm.json), image model, and video model (models.json) all swap independently — JSON edits, no code change.

Graceful degradation everywhere

Premium model → fallback → Kling → free Ken Burns. A render rarely hard-fails; creators lose trust on a crash far more than on a cheaper fallback.

04
Architecture rule (hard)

Mode-hooks, not parallel pipelines

Brand and Studio are thin additive layers over the shared engine — a payload merge, a guard, a post-pass. The clip builder and assembler never know which door they were called from.

Shared core

script_parser → scene_intelligence → model_router → image_generator → clip_builder → assembler

Brand hook

Brief extraction (parse-only), mandatories hard-block, product-beat passthrough, disclosure + CTA post-pass.

Studio hook

Shot planner expands a brief to the same frames[]; reusable Talent/Product identity locks faces & products across shots.

No databaseNo message brokerNo auth layer in the hot path*State keyed by run_id

*Operator JWT auth gates money/rights routes; durable job DB is a roadmap item (SCALE_PLAN Phase 0).

06
The core data model

Everything flows through one mutable frame dict

Each stage reads some keys and writes others. Stages are order-dependent (each needs what the last wrote) but internally parallel — per-frame work runs in thread pools.

  • Identity / text — caption, duration, director note.
  • Source selection — photo_spec (real | ai_portrait | ai_symbolic), resolved visual_path, model overrides.
  • Direction — scene{emotion, image_prompt, motion_prompt, camera}.
  • Cast / speaker — speaker_id + cast[] with gender/age/voice.
  • Mode extras — product_beat (brand), talent_id / product_id / continuity_lock (studio).

Why a single fat dict

A flat, mutable record lets every agent be a pure-ish transform with no shared service. Adding a feature is usually: parse a new annotation → set a key → consume it downstream. The whole-reel treatment rides on frames[0]["_treatment"].

09
Safety & governance invariants

Four gates, each catching a different failure class

The gates

  • Gate A — script moderation (non-blocking on API error).
  • Gate B — face sanity after image gen (≤2 retries).
  • Gate B2 — vision critique: no blank/abstract still when a real subject was expected.
  • Brand gate — mandatories hard-block before any spend.

The invariants

  • Real media & product beats are never AI-regenerated.
  • AI never writes brand ad claims — copy is operator-supplied verbatim.
  • AI likeness of a named real person requires recorded consent (face & voice).
  • Consent + spend-cap gates pass before any paid / external render.

Upfront credit visibility

Live per-vendor balance probes (ElevenLabs, Kling, Suno, fal) surface a low wallet before a run, not mid-render. Read-only, concurrent, degrades per-vendor.

Spend governance

reserve → release → settle, append-only cost ledger, stale-reservation sweep on startup. A crash can't permanently inflate a cap.

11
Cross-cutting: resilience

Everything degrades, never crashes

  • Failure isolation — a per-frame failure falls back for that frame only; the render continues.
  • Capped parallelism — pools throttled to the strictest vendor limit (Kling 4, Veo 2); retry-on-limit instead of dropping frames.
  • Editor iteration loop — per-frame redo, progressive reveal, approval gate. Animate only approved frames; the rest fall back to free Ken Burns.
  • Restart-safe metadata — run payload/status/log bridged to SQLite stand-ins ahead of the full DB.

Concurrency & failure matrix

Scene design pool (10) → generic fallback · Image gen serial → fallback model + retries · Lip-sync 2-phase → clears & animates normally · Clip build → retry-on-limit then Ken Burns · Assembly single ffmpeg → temp dir preserved for debugging.
