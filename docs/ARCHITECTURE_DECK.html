HLD §1 · Purpose & Scope

Four front doors. One engine. Never fork the pipeline.

Every mode builds the same frames[] data model and calls the same agents/* stages. Modes are thin hook layers and flags into _run_inner — parallel pipelines are forbidden by design.

Defining principle

Realism preservation — real user media is never AI-regenerated — plus test-cheap / finish-expensive: cheap models in Dev, premium only for final renders.

Out of scope (today)

Multi-tenant accounts · persistent job DB · batch/queue production · kinetic motion-graphics (B2) · CLIP scoring — all on the roadmap.

HLD §4 · Core Data Model

The frame dict — the only currency of the pipeline

frame = {
  "frame_id" "caption" "duration" "director_note" # identity / text
  "photo_spec" "visual_path" "*_model_override" # source selection
  "scene"{emotion, image_prompt, motion_prompt} # direction
  "speaker_id" "cast"[…voice_id] # cast / speakers
  "lipsync" "voice_override" "lipsync_clip_path" # lip-sync
  "product_beat" "suggestions" # brand mode
  "talent_id" "product_id" "continuity_lock" # studio mode
  "caption_position" "caption_max_lines" # per-frame captions
}

Whole-reel plan (arc, motif, shot-size rhythm) rides on frames[0]["_treatment"].

Pipeline = transformations

Each stage reads some keys and writes others over the same mutable list. Stages are order-dependent…

…but internally parallel

Per-frame work fans out in ThreadPoolExecutors, throttled by the strictest provider concurrency cap in flight.

Why it matters

One schema shared by all four modes is the mechanism that keeps Story, Brand, Studio and Canvas on a single engine.

One source of cost truth

💳 Live credit visibility

✅ Approval gate

Editors tick frames after previewing stills; only approved frames get paid animation — the rest fall back to free Ken Burns, and the quote drops to match.

LLD §13–14 · Animation & Assembly Internals

The two hardest problems: provider limits & audio drift

Two-phase clip building

_fit_clip_to_duration() trims or freeze-extends every clip before caching, so cached entries are always the right length.

Effective timecodes — the sync law

offset[i] = Σ durations[:i] − 0.4·i
# crossfade overlap per junction

Captions, voiceover adelay, ducking windows and lip-sync placement must all use effective_timecodes() — raw cumulative durations drift at every crossfade.

Beat-aware cutting (anti-slideshow)

beat_track finds music onsets; a cut near a beat becomes a ~0.06s hard cut on the beat, else a 0.4s dissolve. Cuts and captions are computed from the same overlap list — they can never desync.

LLD §17 & §19 · Concurrency, Failure & Sharp Edges

Degrade per-frame, never crash the render

StagePool / capOn failure
Scene designthreads ×10generic fallback scene
Image genserial/framefallback model → Gate B retry ×2
Lip-sync6 submit / N pollclear lipsync → animate normally
Clip buildmin(max_concurrent)retry-on-limit → Ken Burns

Degradation ledger (degradation.py) records every silent fallback — vendor failovers, gate skips, music failures — surfaced as the 🧾 render report.

Sharp edges (read before editing)

  • pricing.estimate must mirror model_router exactly — or the quote diverges from the bill.
  • Kling/Higgsfield cache keys are deliberately legacy-formatted — "cleaning them up" throws away paid clips.
  • All audio timing goes through effective_timecodes() — anything else drifts at crossfades.
  • subject_name is always optional — never default a sample person; derive from the story via cast.subject_descriptor().
  • Every spend route calls reserve_spend before dispatch — including /retry; caches don't protect a cold path.

HLD §8–9 · Risks & Roadmap

Where it's headed

Top risks (mitigated, not solved)

  • In-memory web run state — restart loses in-flight runs → durable job store is Scale Phase 0
  • fal.ai slugs/prices marked VERIFY — Dev is safe; verify before paid runs
  • Lip-sync media leaves the box (external CDN) — opt-in, documented; signed URLs on roadmap
  • No automated tests — router / pricing / cast are pure functions, prime unit-test targets

Roadmap

  • Shipped: P0–P2 — gates, cast, treatment, lip-sync, B-roll, voiceover, brand B1, canvas hardening (L99)
  • Next: Scale Phase 0 durability — persistent runs DB, resume, cost ledger, backups
  • Then: Phase 1 job queue + multi-worker · B2 kinetic motion-graphics · P3 CLIP scoring
